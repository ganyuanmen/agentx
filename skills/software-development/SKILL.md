# 软件开发

## 适用条件
用户要求在某个代码仓库内新增功能、修复缺陷或重构。

## 步骤
1. 先用 list_files / search_text 摸清相关模块，不要凭猜测改文件。
2. 读目标文件后再改；改动范围以任务描述为界，不顺手重写无关代码。
3. 修改后运行项目声明的验证命令（typecheck / test / lint），把真实输出贴出来。
4. 若验证失败，先定位是本次改动引入还是既有问题，再决定修还是报告。

## 约束
- 不删除既有有效逻辑；需要偏离时说明理由。
- 不把密钥、令牌写进代码或日志。
- 测试未跑通时不得声称完成。
