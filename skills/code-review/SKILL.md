# 代码审查

## 适用条件
用户要求 review 某个文件、目录或补丁。

## 步骤
1. 读完整上下文（被改文件和调用方），不要只看 diff 片段。
2. 按严重级别给出问题：blocker / important / nit。
3. 每条问题指出文件、行、原因与建议修复方式。
4. 最后给出结论：通过 / 有条件的通过 / 不通过。

## 约束
- 不臆测未读过的代码行为。
- 区分"真实缺陷"与"个人偏好"，偏好要标注为 nit。
