# ADR-006：TUI 采用「终端能力探测 + 降级」策略

日期：2026-10-22
状态：已采纳

## 背景

第一版 CLI 输出只有朴素文本，与参考产品（Hermes Agent）差距明显。用户要求做同类界面：
ASCII 艺术字 logo、带标题的圆角边框面板、工具清单、彩色状态。

但 agentx 有一条硬约束（PM_SPEC §5.2 / 上游需求 §5.2）：

> 标准输出保留最终回答，便于管道使用。

同时 `--json` 是脚本接口，必须保持机器可读。

## 决策

界面能力按运行环境**分三档自动降级**，不做开关配置：

| 环境 | 判定 | 行为 |
|---|---|---|
| TUI 模式 | stdout 是 TTY 且 `TERM != dumb` 且未设 `NO_COLOR` | 完整界面：logo、面板、颜色、spinner |
| 纯文本模式 | stdout 是 TTY 但有 `NO_COLOR` 或 `TERM=dumb` | 同样的版面结构，但**无 ANSI 颜色**、无 spinner 动画 |
| 静默模式 | stdout 不是 TTY（管道/重定向）或 `--json` | 只输出最终答案 / 一行 JSON，绝不输出装饰 |

这三档由 `createUi()` 在启动时一次性判定，全流程复用同一个对象，避免各处重复判断。

## 为什么不用现成 TUI 库（ink / blessed / cli-ui）

- ink 需要 React 运行时，为一个 CLI 拉起一整套渲染树，与「依赖应保持精简」（需求文档 §3）冲突；
- blessed 体积大、维护停滞，且会接管整个终端（alt-screen），破坏「stdout 保留最终回答」；
- 我们需要的只是「颜色 + 边框 + 少量光标控制」，用 Node 内置能力 200 行内可完成。

因此：**零新增依赖**，只用 `node:process` 的 `isTTY`、ANSI 转义序列与 `readline`。

## 具体实现约束

1. **宽度自适应**：面板宽度 = `min(process.stdout.columns ?? 80, 100)`，最小 40；边框字符按显示宽度计算（CJK 字符占 2 列，用 `string-width` 逻辑自实现，不引依赖）。
2. **Logo 两种尺寸**：终端宽度 ≥ 96 用大号 ANSI Shadow 艺术字；否则用单行紧凑版，避免折行破坏版面。
3. **降级不丢信息**：无颜色时仍有清晰的区块标题与分隔线；spinner 退化为静态 `...`。
4. **绝不在非 TTY 下写 ANSI**：既避免污染管道，也避免写入日志文件。
5. **logo 与面板只在 `chat` 启动时打印一次**，`run` 命令不打印（保持脚本友好）。

## 后果

- 新增 `packages/cli/src/ui.ts`（约 400 行），无新依赖；
- `chat` 的启动横幅、工具面板、状态行改由 `ui` 渲染；
- 管道输入（`printf 'hi\n/exit\n' | agentx chat`）行为不变，仍是纯文本 + 不挂起；
- 需要为 `ui` 补单元测试：TTY/非 TTY 判定、CJK 宽度计算、logo 宽度分支、无颜色降级。
